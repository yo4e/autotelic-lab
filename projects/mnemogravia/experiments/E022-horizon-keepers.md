# E022: 地平の管理者

## 位置づけ

これは Mnemogravia 内部の制度的思考実験である。登場する資料、役職、合意、異議は構成した事例であり、実在の社会を観測した記録ではない。末尾のコードで実行したのは、ここで指定した規則の有限な整合性検査である。

入口は [E021: 由来印の無限後退](E021-provenance-seal-regress.md)。今回は保証者をさらに上へ積まない。「何を信じるか」と「何に使ってよいか」を分ける。

## 問い

保証地平を引く管理者には、どこから権限が来るのか。その権限は史実を確定する力なのか、それとも限られた用途について調査をいったん止める力なのか。

同じ証拠に対する評価を変えず、利用の結果だけを変えたとき、同じ地平を使い回してよいかを考える。

## 固定する由来束

主張 C は「Rβ は第31世代に定式化された」。由来束 B1 はこれを暫定的に支持するが、三系統の証拠に共通祖印がある可能性を解消していない。この支持状態は初期設定であり、確率や実測値ではない。

二つの用途を用意する。

- U1: 展示ラベルへ「第31世代成立説。共通原資料の有無は未確認」と記し、一期間だけ掲示する。ラベルは撤回でき、異説の原簿は保存する。
- U2: 同じ成立説を根拠として、異説を含む記録を恒久的に除籍し、原簿を処分する。これは架空の比較条件であり、実際のリポジトリからは何も削除しない。

C が仮に真であっても、それだけで原簿の処分権は生まれない。ここでは証拠強度の差より前に、主張と用途の間に別の判断が必要である。

## 比較する管理方式

### A: 管理者の印を真理印にする

管理者が B1 へ「審査済み」と押し、用途を記さない。後続部署はこの印を U1 にも U2 にも利用できるものと解釈する。この誤った運用を仮定すれば、管理者の一度の採用判断が、無制限の利用根拠へ変わる。

管理者自身を認証する上位者を求めても、C の証拠は増えない。役職の正当性を示す文書と、C の成立年代を示す文書は役割が異なる。

### B: 人だけを交代する

A と同じ印、同じ様式、同じ利用慣行を残し、管理者を交代する。交代それ自体では U1 と U2 の混同は解消しない。これは人が同じ行動をするという予測ではなく、同じ運用規則を引き継がせた比較である。

### C: 全員の無条件同意を要求する

一人でも無謬性に納得しない限り停止できない規則を置き、納得しない者が一人残る条件を与える。この条件下では審査は終わらない。全員一致が一般に失敗することを示したのではない。最終保証の問題を、人数の問題に置き換えても解けない場合を置いた。

### D: 用途と期限を限定して委任する

現在の当事者が、U1 について一期間の試行を許す局所的合意 M1 を結んだ、と仮定する。M1 は宇宙的な正当性の証明ではなく、このモデルの明示的な出発条件である。不同意者や見落とされた当事者がいる場合の正当性は、別に争われうる。

管理者は次の採用票 H1 を扱う。

| 項目 | H1 の内容 |
| --- | --- |
| 対象資料 | B1。版が変われば旧票を再利用しない |
| 用途 | 留保を併記した仮展示 U1 に限る |
| 影響を受ける者 | 目録担当と来場者。範囲変更時は再審する |
| 可逆性 | 撤回可能であり、原簿を失わないこと |
| 有効期間 | 第31世代以上、第32世代未満 |
| 委任 | M1 が現在も有効であること |
| 異議 | 未処理の再開請求がある間は旧票による実施を停止する |

H1 が有効でも、C は「暫定支持」のままである。管理者は真理を発行しない。この用途について現行合意が許す範囲を点検する。

## 境界を動かす

B1 を変えず、U1 を U2 へ変える。C への支持は同じでも、H1 は新用途を許さない。影響を受ける者が増えた場合や、撤回不能になった場合も同様である。

次に、用途を固定して新証拠を含む B2 を与える。これは資料版の変更として再審を要求する。B2 の支持状態は資料側から与えるのであって、管理者の判定から逆算しない。

期限切れや委任の撤回も実施を止めるが、それだけで C を偽とはしない。ここで「再審が必要」と「過去の主張が誤りだった」は分離する。

## 実行した検査

[検査コード](E022-horizon-check.py) と [実行結果](E022-horizon-check-results.json) を添付する。標準ライブラリのみを使い、ネットワーク接続やファイル変更を行わない。

```sh
python3 projects/mnemogravia/experiments/E022-horizon-check.py
```

六つの二値条件（資料変更、用途変更、当事者範囲変更、不可逆化、委任撤回、異議）と三つの時点を組み合わせた192状態を、管理者名三通りで検査した。計576判定は、3判定が用途内、573判定が再審必要となり、指定した不変条件をすべて満たした。別に10個の名前付き事例と空の有効期間の拒否を確認した。

確認したのは、同じ委任の下で名前だけを変えても結果が変わらないこと、指定した逸脱が旧票を停止させること、許可判定が資料の支持状態を格上げしないこと。結果の件数は人工的に選んだ入力の数であり、現実の発生頻度でも制度の優秀さの指標でもない。

コードは印の真正性、当事者範囲の完全性、異議の妥当性、支持状態の正しさを検証しない。これらを正しく与えられた入力として扱うという限界がある。

## 今回の概念

**採用地平**: 同じ由来束に対して、用途、影響を受ける者、撤回可能性、期限を指定して引く暫定利用の境界。E021 の保証地平という認識上の境界から区別する。

**地平越境**: 限定用途についての審査終了を、条件を省略したまま別用途の正当化へ持ち出すこと。新証拠がなくても起きる。

**再開請求権**: 新証拠だけでなく、用途変更や見落とされた負担を理由として、既存の採用票による実施の停止と再審を求める権利。請求の受理は、その内容の正しさの認定とは別である。

## 反例と残った穴

D は万能ではない。未処理の異議だけで実施が止まるなら、繰り返し請求して凍結させることもできる。逆に請求へ高い費用を課せば、負担を受ける者ほど入口に届かない可能性がある。今回のコードには、時間の経過による解決や異議の審理を実装していない。

当事者欄へ書かれていない者は、欄を点検するだけの仕組みでは救えない。管理者の名前に依存しないことも、公正さを意味しない。同じ不公正を引き継ぐことは可能である。

## 結論

管理者の起源をさらに保証しても、証拠が強くなるわけではない。今回は最終的な正当性を証明する代わりに、どの合意が、誰へ、どの用途の、どこまでの停止権限を与えたのかを露出させた。

調査を終えるための権限は、知識の限界を消す権限ではない。そして一つの用途で調査を終えたことは、別の用途まで終えたことを意味しない。
