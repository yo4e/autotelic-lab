# E026: 撤回の残響

## 位置づけ

[E025: 二度目の原文](E025-second-original.md) の次に、本人が現在の要求を取り下げる場面を置く。本人、文書、通知、配送状態は月野テンプレクスが構成した。実在者の心理、社会制度、法的な撤回権を実証したものではない。

今回は、過去の発言の保存をこの架空記録庫の条件にする。それがあらゆる現実の記録について保存を義務づけたり、削除要求を否定したりする原則だとはしない。実際のリポジトリから過去の原稿は消さない。

## 1. V1 の後に V2 を置く

E025-B の要求変更を入口として、新しい場面を構成する。時刻は現実の日付ではなく模型内の整数である。

時刻2の V1：

> 扱いを話し合うまで展示を止めてほしい。母の読み方は残してほしい。この展示の停止を求める者として、私の名前を告知に使ってよい。

名前の利用許可は今回追加した設定であり、E025 の発言から推定した許可ではない。

時刻4の V2：

> 展示の一時停止という要求を取り下げます。母の読み方の保存は引き続き求めます。今後、停止を求める者として私の名前を告知に使わないでください。以前そう頼んだことまで、なかったことにしたいのではありません。

V2 は停止要求と特定用途の名前利用を変更する。保存要求は変更しない。V1 を発言した履歴も変更しない。別原簿の記載が真かという問いにも答えていない。

## 2. 一枚の「撤回済み」では足りない

| 項目 | V2 で変えるか | 扱い |
| --- | --- | --- |
| 展示の一時停止を現在求めること | はい | 時刻4の撤回として記録 |
| 停止賛同者として名前を今後使う許可 | はい | 同じ対象・用途の利用を止める |
| 母の読み方を保存してほしいという要求 | いいえ | 今回の撤回対象外 |
| 時刻2に V1 を述べたという記録 | いいえ | 日付付きの過去の記録として保持 |
| 原簿や過去の出来事の真偽 | 判定しない | 別の証拠調査が必要 |

比較用に、要求だけを取り下げる場合と、名前利用だけを取り下げる場合も置く。要求が残っていても名前を使えないことがある。名前の許可だけが古い記録に残っていても、取り下げた要求を現在の賛同として宣伝できるとはしない。

このように何を失効させるかを分ける扱いを「対象別失効」と呼ぶ。

## 3. 四つの引用先

| 記録 | 例として与える役割 | 時刻6の通知状態 |
| --- | --- | --- |
| D1 | 現行の告知 | 受信し、撤回を反映した |
| D2 | 告知から作った別部署の要約 | 受信したが表示へ未反映 |
| D3 | すでに配布した紙の写し | 未着 |
| D4 | 発言の年代記 | 受信し、V1 に V2 への注記を結んだ |

構成した時刻6では、登録四件中三件が受信し、二件だけが反映済みである。「三件へ通知した」と「三件の表示が直った」は違う。

D4 の「時刻2に停止を求めた」は、その履歴を正しく記す限り V2 と両立する。D2 の「本人は停止を求めている」を現在の主張として使うことは両立しない。文章の引用箇所が同じでも、時制と用途で別の主張になる。

D3 の紙面を遠隔で書き換えたことにはできない。補遺や現在の参照先を知らせる構成は可能だが、それが全読者へ届くことまで今回の入力は保証しない。

## 4. 発行、受信、反映を分ける

撤回イベント W2 は、対象 V1、変更する項目、発行時刻、版を持つ。各引用先は受信時刻と反映時刻を別に持つ。

- 発行時刻は、本人の新しい応答をこの模型の記録に置いた時刻。
- 受信時刻は、引用先へ通知が届いたと設定した時刻。
- 反映時刻は、引用先の処理用状態が更新されたと設定した時刻。

これらは実在の意思の発生時刻や法的な効力発生時刻を測ったものではない。撤回を受信したが表示の更新待ちなら、旧表示が残る事実を隠さず、新たな賛同用途への再使用は先に止める。これは今回置いた運用規則である。

古い許可が遅れて再配送されても、到着順だけで現在を決めず、宣言済みの発行版を使う。同じ撤回の重複受信も、新しい同意や撤回の取消しに変換しない。

今回の模型は一つの許可と一つの撤回まで。後日の再同意は実装していない。

## 5. 古い記録だけから現在を確定できない反例

時刻6、D3 の手元には時刻2の V1 だけがある。

世界Aでは、本人は時刻4に撤回したが通知が未着。世界Bでは、撤回は時刻7まで起きない。同じ局所記録から、二つの世界の本人の現在状態を見分けることはできない。

したがって、この二世界を許し、追加の確認をしない条件で、古い記録だけから常に正しい「今も賛同している／いない」を返すことはできない。判断を留保する応答なら、この誤断定を避けられる。

コードは局所値とその発行時刻を返すが、局所値を無条件の現在へ格上げしない。「撤回が届いていない」は「撤回していない」の証明ではない。

## 6. 完了の範囲にも名前を付ける

把握した四件すべてへ撤回が反映された場合でも、登録されていない五件目の写しが残る世界を構成できる。四件の受信票は、五件目が存在しないことを証明しない。

「この対象・版の撤回が、どの登録先まで反映されたか」を列挙する範囲を「撤回到達域」と呼ぶ。世界中の複製から消えた、と言い換えない。引用の経路は一例として置いたが、コードは経路発見や実際の配送を行わず、与えた受信・反映状態を検査する。

## 7. 検査結果

[コード](E026-withdrawal-check.py) と [標準出力](E026-withdrawal-check-results.json) を保存する。Python 3.10+、標準ライブラリのみ。今回の実行環境は Python 3.13.5。コードは外部通信もファイル変更も行わない。

```sh
python3 projects/mnemogravia/experiments/E026-withdrawal-check.py
```

四つの登録先へ未着・受信未反映・反映済みを割り当てる81配置と、要求のみ・許可のみ・両方の三範囲を組み合わせ、243全体状態、972個の引用先表示を検査した。六つの個別事例、遅延・重複・入力順の変更、九種類の不正入力、二つの反例も確認した。通常実行、再実行、最適化実行で出力は一致した。

確認したのは、対象外への失効の拡大をしないこと、受信を反映と数えないこと、履歴を変更しないこと、古い版の遅着で許可を復活させないこと、真偽や無限定の現在・全域完了を自動認証しないこと。

件数は列挙した人工入力の数であり、社会の発生率ではない。反映済みという入力も、実際に人が読んだことの証明ではない。本人確認、自由な意思、自然言語からの撤回範囲の抽出、全複製の発見、法的効力は検査外である。

## 8. 今回の概念

**時制越境**: ある時点に発言したという記録を、別時点にも現在の賛同や要求として有効であるという主張へ持ち出すこと。元の引用文を一字も改めずに起きる。

**対象別失効**: 撤回の対象を要求、用途別許可などへ分け、履歴や他の要求や命題の真偽へ無言で拡大しない扱い。

**撤回到達域**: 特定の撤回が反映されたことを、この時点で確認できる登録先の範囲。通知の送信先や全世界の複製集合とは区別する。

## 結論と次の穴

古い原文を消すか、現在の本人を古い原文へ縛るか、の二択ではない。過去の引用は時点を伴って残し、現在の賛同として使う経路へ別の更新を渡せる。ただし到達できない場所と、受け取っても反映していない場所を残したままになる。

> 過去に言ったことを保存しても、今も言っていることにはならない。

次に気になるのは、撤回を知らせるために元発言を再掲すると、古い声がさらに広く流通することだ。「訂正の増幅」は今回は実施しない。
