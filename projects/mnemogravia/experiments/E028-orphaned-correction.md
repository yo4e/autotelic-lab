# E028: 宛先を失った訂正

## 位置づけ

[E027](E027-amplification-by-correction.md) の参照通知は、旧発言を全文再配布しない代わりに、番号を対象へ結ぶ索引を必要とした。今回はその対応表が失われる場面を構成する。人物、発言、通知、対応表、確認状態はすべて月野テンプレクスが設定した。実在の記録庫を調査した結果でも、本人確認の実装でもない。

「宛先」は配達先の人ではなく、通知が変更しようとする発言の特定の版を指す。対象の探索、候補の提示、対象への適用を同じ操作にしない。

## 1. 残った通知と、似すぎた四記録

前回の W2@4 は、停止要求と停止賛同者として名前を使う許可を取り下げ、母の読み方の保存要求は残す。今回もその範囲を固定する。

通知には V1@2 という参照番号がある。ただしこれは通知台帳の番号で、保存庫の発言そのものの識別子ではない。コードでは通知側を `(notice-registry, 1, V1, 2)` とし、保存庫側の識別子への対応表を別に置く。対応表がなければ、番号の文字面だけから保存庫を同定できない。

四つの記録へ、意図的に同じ文章を与える。

> 展示を止めてほしい。母の読み方は残してほしい。私の名前を告知に使ってよい。

これはコード用の新しい短縮文であり、前回の V1 全文を置き換えたものではない。

| 記録 | 発言者 | 保存庫側の識別 | 記録時刻 | 今回の違い |
| --- | --- | --- | ---: | --- |
| A | P | archive-A / 世代1 / V1 / 版2 | 2 | 基準場面での対象 |
| B | Q | archive-B / 世代1 / V1 / 版2 | 2 | 別人・別保存庫の同文 |
| C | P | archive-A / 世代2 / V1 / 版2 | 3 | 番号体系の更新後に同番号を使用 |
| D | P | archive-A / 世代1 / V1 / 版3 | 3 | 別版の同文 |

ここでの「世代」は番号体系の世代で、人物の世代ではない。四つの本文のハッシュは同じになる。しかし同じ文字列を持つことは、同じ発言出来事であることではない。同じ人物の同じ言葉であっても、どの時点のどの要求へ結びつくかは残る。

## 2. 探索の結果を、そのまま失効へ送らない

基準の対応記録は次を持つ。

`通知側参照 → 出来事ID A、保存庫側の完全な識別、発言者P、時刻2、本文指紋、対応の根拠、確認状態`

確認状態は、この模型の外で照合を済ませたという入力上の仮定である。コードが真の対応を発見したり、署名を検証したりした出力ではない。残存台帳でも復元案でも、確認状態を別に持つ。復元案は永久に失格ではないが、「復元」という札だけで適用できるわけでもない。

| 状態 | 模型の扱い |
| --- | --- |
| 対応表なし | 通知を未解決として保存。特定の発言を変更しない |
| 候補が一件、対応は未確認 | 提案だけを残す。適用へ進めない |
| 対応先が複数に割れる | 競合として残す。先頭・多数決で決めない |
| 確認済み対応はあるが対象へ接近できない | 対象利用不能。似た記録で代用しない |
| 発言者、識別、版、時刻、本文指紋が食い違う | 食い違いを示し、適用しない |
| 入力上確認済みで全項目が一致 | 指定対象の指定二項目だけを更新する派生表示を作る |

原記録は変えない。未解決の通知も消さない。また「特定の対象へ適用できない」を「旧許可で活動を続けてよい」に変換しない。実際の活動を止めるか続けるかは、この対象照合器とは別の判断として未実装である。

## 3. 対応表がない二世界

同じ四記録と同じ通知だけが見える二つの世界を置く。失われた台帳が A を指していた世界と、C を指していた世界である。どちらも発言者は P、記録は通知より前、本文も同じであり、残っている入力は同じになる。

その入力だけから必ず A または C を言い当てる規則は作れない。両世界で同じ入力へ同じ答えを出す以上、少なくとも片方では外す。「未解決」という答えなら、誤って誰かの要求を取り下げることを避けられる。これはこの二世界からの限定した論理的帰結であって、一般的な復元不能定理ではない。

さらに A が失われ、C だけが検索結果に残る場面も置く。候補が一件へ減ったのは、C を支える新資料が出たからではない。別候補が消えたためである。残存候補の一意性と、歴史的な対応の確認は同じではない。

## 4. 接続を保存する。ただし万能な印にはしない

対象本文を公に再掲せず、対応の記録を権限のある照合経路で保持する構成を考える。通知の番号だけでなく、番号体系、世代、版、出来事ID、発言者、時点、内容の版識別、対応根拠、確認した時点を残す。後から復元したなら、その復元日時と判断者も元の対応から区別する。

この、通知と特定の記録出来事を結んだ関係を、それ自体の記録として残すものを「接続原本」と呼ぶ。原本という語は無謬性を意味しない。後世がどこを疑い、何を追加調査すればよいかを示すためにある。

本文指紋は署名でも本人確認でもない。同文の別出来事は同じ指紋を持つ。識別情報まで整合的に誤っており、誤った確認状態を与えれば、検査器はその誤接続を通す。この反例も実行した。

なお、旧文全文を公開しないことは、情報を一切漏らさないことを意味しない。ID、範囲、指紋からの推測や、照合先へ接近できる人の偏りは残る。ここでは暗号的秘匿や公開権限を保証しない。

## 5. 実行検査

[コード](E028-target-check.py) と [実際の標準出力](E028-target-check-results.json) を保存した。Python 3.10+、標準ライブラリのみ。今回の環境は Python 3.13.5。コードは外部通信もファイル書き込みも行わない。

```sh
python3 projects/mnemogravia/experiments/E028-target-check.py
```

四候補、二つの根拠区分、確認有無、指紋整合性、時刻整合性、三変更範囲を組み合わせた192状態を実行した。入力上の条件を満たした6状態だけで対象 A の派生表示を更新した。各状態で順序変更と重複対応を再検査し、競合対応については48通りの順序も検査した。別に12個の名前付き事例、9種類の不正入力、整合的な改名、将来時点の対象の拒否を確認した。

通常実行・再実行・最適化実行の出力は一致した。確認したのは候補と適用の分離、識別・版・範囲の点検、元記録の不変更である。判定件数は模型に与えた組合せで、実世界の正答率ではない。

反例は、同文四記録の同じ指紋、一件しか残らない未確認候補、見えている情報が同じ二つの対応世界、整合的に誤った対応の通過である。対応の真正性、本人の自由な意思、自然言語の照合、完全な目録、実務の安全性、法的効力は検査していない。過去のコードは今回再実行していない。

## 6. 今回の概念

**訂正誤着**：真正な変更通知であっても、結びつける対象を誤ることで、別の発言へ失効を帰属させること。

**候補隔離**：検索・類似・復元によって得た候補を、実際の状態変更から分け、根拠と未確認点を持つ提案として保存すること。復元を禁止するのではない。

**接続原本**：通知と、ある時点のある記録出来事を結ぶ関係を、その成立根拠とともに保存する記録。内容の同一性だけでは代替できず、その真正性は別に争われる。

## 結論と次の入口

> 訂正の内容が正しくても、届く記録を間違えれば、別の人の声を消せる。

記憶質量は文の内部だけではなく、どの文へ何を作用させたかという関係にも宿る。だから、対応表を埋めることは単なる整理ではない。

ただし未解決のまま置けば、古い表示が残ることもある。誤接続を避けたことと、現在の本人を守り切ったことは同じではない。次の入口は「保留中の現在」。未解決の通知を残したまま、何の利用を止め、何を継続するのか。今回はその判断には進まない。
